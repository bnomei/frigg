## Context

Add a read-only utility command:

```bash
frigg hash
```

It emits exactly one machine output:

```text
frigg-hash=<hex>
```

If `$GITHUB_OUTPUT` exists, write the same `frigg-hash=<hex>` line there. Do not emit paths, debug fields, component fields, runner OS/arch, restore prefixes, human explanations, or install locations.

The command must not require a workspace root and must never create, read, or write `.frigg/`. It should be handled as a normal non-serve utility command and return after printing.

The hash should be derived only from Frigg-owned stability inputs, such as `env!("CARGO_PKG_VERSION")`, latest storage schema version from migrations, retrieval projection/index contract versions, and index-affecting defaults or feature/config knobs. Prefer a small library-owned helper for the stable hash material so `cli_runtime` does not hardcode storage or projection internals.

## DoD

- `Command::Hash` exists and dispatches to a focused command handler.
- `frigg hash` prints exactly one `frigg-hash=<hex>` line to stdout.
- When `$GITHUB_OUTPUT` is set, the command appends exactly the same key/value line there.
- The command is deterministic for a given build/config and has no `.frigg/` side effects.
- Hash material is centralized enough that future storage/index contract changes have one obvious place to update.

## Validation

- `cargo test -p frigg hash`
- A test proves stdout contains one `frigg-hash=<hex>` line and no other text.
- A test proves `$GITHUB_OUTPUT` receives the same line.
- A test proves command config resolution does not require a workspace root.

## Escalate If

- Storage schema or projection versions are not accessible without exposing broad internals; add a narrow library helper rather than duplicating constants in the binary crate.
