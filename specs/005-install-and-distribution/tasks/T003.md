## Context

Update README install docs so prebuilt install paths are first. Keep Homebrew near the top, move `cargo install frigg` to a Rust/developer fallback, and keep local checkout build as a developer path.

Document the curl installer with a version-pinnable example and explain that it installs only the `frigg` binary. Do not claim it runs setup, starts services, registers MCP clients, or adopts repositories.

Current setup docs remain install plus:

```bash
frigg init
frigg verify
frigg reindex
frigg serve
```

Do not claim `frigg adopt` behavior until that command exists.

Add GitHub Actions guidance:

- Default no-cache workflow: checkout, install pinned Frigg version, run `frigg init`, `frigg reindex`, `frigg verify`.
- Optional `.frigg/` cache workflow: restore `.frigg/`, run `frigg init`, `frigg reindex --changed`, `frigg verify`, save only on trusted events.
- Optional binary cache only as an advanced note: exact key only by Frigg version and runner platform; no broad restore keys for cached executables.
- Show `frigg hash` as the single Frigg-owned cache fingerprint for `.frigg/` cache keys. Workflow YAML owns runner OS/arch, `github.sha`, restore prefixes, and cache paths.

Warn that `.frigg/` is build output/provenance and not a secret store.
