## Context

Add `scripts/install.sh` as a standalone POSIX `sh` installer for existing GitHub Release assets. It must support `FRIGG_VERSION`, `FRIGG_INSTALL_DIR`, `FRIGG_REPOSITORY`, `FRIGG_INSTALL_DRY_RUN`, and test-only target overrides `FRIGG_INSTALL_OS`, `FRIGG_INSTALL_ARCH`, and `FRIGG_INSTALL_TARGET`.

Use the current asset contract: Unix archives are `frigg-v<VERSION>-<TARGET>.tar.gz` with adjacent `.sha256` files. Release tags use `v<VERSION>`. For explicit versions, normalize `0.5.0` and `v0.5.0` to tag `v0.5.0` and asset `frigg-v0.5.0-<TARGET>.tar.gz`. For latest installs, resolve the latest tag/version before constructing the asset URL.

Supported installer targets are:

- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`
- `x86_64-apple-darwin`
- `aarch64-apple-darwin`

Linux messaging must say GNU/glibc Linux; do not imply Alpine/musl support. Windows remains manual release asset download.

The installer must only install the `frigg` binary. It must not run `frigg init`, `frigg verify`, `frigg reindex`, `frigg serve`, register clients, edit source files, or mention/attempt `adopt`.

Use HTTPS/TLS curl flags:

```sh
curl --fail --location --proto '=https' --tlsv1.2 --silent --show-error
```

Download to a temp dir, verify `.sha256` before extracting, then install. Verification must support `sha256sum --check`, `shasum -a 256`, and `openssl dgst -sha256`. If no checksum verifier exists or verification fails, exit without installing.

Avoid `sudo`; default install directory is `$HOME/.local/bin`. If `$GITHUB_PATH` exists, append the install directory after successful install.

## DoD

- `scripts/install.sh` is POSIX `sh` compatible and structured around functions with a final `main "$@"`.
- Help and dry-run output expose the resolved target, version/tag, archive URL, checksum URL, and install dir without downloading.
- Target detection covers the four Unix release targets and rejects unsupported targets clearly.
- Checksum success and checksum failure are testable without live GitHub network.
- The installer fails before install when checksum verification is impossible or fails.
- The installer never runs workspace setup/index/service/client commands.

## Validation

- `sh scripts/install.sh --help`
- `FRIGG_INSTALL_DRY_RUN=1 sh scripts/install.sh`
- `FRIGG_VERSION=v0.5.0 FRIGG_INSTALL_DRY_RUN=1 FRIGG_INSTALL_TARGET=x86_64-unknown-linux-gnu sh scripts/install.sh`
- `FRIGG_INSTALL_DRY_RUN=1 FRIGG_INSTALL_OS=Darwin FRIGG_INSTALL_ARCH=arm64 sh scripts/install.sh`
- `dash scripts/install.sh --help` when `dash` is available.
- Run any installer fixture tests added by this task.

## Escalate If

- Latest release resolution cannot be made testable without live GitHub access.
- POSIX `sh` compatibility conflicts with mandatory checksum behavior.
