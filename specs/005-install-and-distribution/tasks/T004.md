## Context

Add `.github/workflows/frigg-install-cache.yml` to dogfood the install/cache path this spec documents.

The workflow should run on pull requests and workflow dispatch. It may also run on `push` to `main` if that is the trusted cache-save path. Use `actions/checkout@v5` to match existing workflows.

Expected flow:

1. Check out the repository.
2. Run `frigg hash` and use `steps.<id>.outputs.frigg-hash` in cache keys.
3. Install Frigg through `scripts/install.sh` with a pinned version or with a local dry-run/install fixture if release-network use is not acceptable for CI.
4. Restore optional `.frigg/` cache using runner OS/arch plus `frigg-hash` plus `github.sha`, with a restore prefix ending after `frigg-hash`.
5. Run `frigg init`, `frigg reindex --changed`, and `frigg verify` from the checkout root.
6. Save `.frigg/` only from trusted events, such as `push` to `main` or manual dispatch, never arbitrary pull requests.

Do not make a restored cache the final freshness step. Do not cache secrets. Do not require semantic-provider credentials.

## DoD

- Workflow exists and is named for Frigg install/cache dogfood.
- Workflow exercises installer plus `init`/`reindex --changed`/`verify`.
- Cache key includes runner OS/arch, `frigg-hash`, and `github.sha`.
- Restore prefix permits previous commits for the same runner/frigg hash.
- Cache save guard excludes untrusted pull-request events.

## Validation

- Inspect workflow YAML for trusted-trigger save guards.
- Validate workflow syntax with available local tooling, such as `actionlint` if installed.
- Confirm workflow commands match `scripts/install.sh` and `frigg hash` contracts.

## Escalate If

- The workflow needs live GitHub Release downloads but project policy requires network-free PR CI; use a fixture/dry-run smoke path and leave live install to workflow dispatch.
